# army-pr360 — 육군 모집홍보 기록·분석·기획 스킬

## 공통 원칙 (모든 모드에 적용)

1. 모드는 ① 기록 → ② 분석 → ③ 기획 순서로 실행한다.
   사용자가 모드를 지정하지 않으면 "어느 단계부터 할까요?"라고 한 번만 묻는다.
2. ③의 입력은 ②의 추천 1순위 객체를 그대로 받는다.
   사용자에게 다시 입력하게 하지 않는다. 이것이 이 스킬의 핵심이다.
3. 출력 형식은 아래 각 모드의 항목 번호와 순서를 그대로 따른다.
   항목을 빼거나 순서를 바꾸지 않는다.
4. 계산하지 않은 수치를 문장에 쓰지 않는다.
   모든 비율에는 표본 수를 함께 밝힌다.
5. 출력 직전에 반드시 references/시연규칙.md 의
   「출력 전 자가 점검 5문」을 수행한다.

## 참조 파일 사용 시점

| 파일 | 언제 읽는가 |
|---|---|
| references/코드표.md      | 모드 ① 실행 시 |
| references/지표정의.md    | 모드 ② 실행 시 |
| references/시연규칙.md    | 모든 모드의 출력 직전 |
| assets/카드뉴스.html      | 모드 ③ 실행 시 |
| assets/한빛대_시드.json   | 모드 ② 실행 시 누적 데이터가 없을 때 |

## 모드 ① — 현장 기록

**트리거** : "현장 기록", "활동 메모", "오늘 활동 입력", 또는 활동 내용이 담긴 자연어 문장

### 입력
자연어 활동 메모 1~3줄.
예) "오늘 한빛대 부스 운영, 상담 23명, 공병 관심 많았고
     여학생 문의 다수, 포스터 150장 배포"

### 처리
1. references/코드표.md 를 읽는다.
2. 메모에서 아래 항목을 추출한다. 코드표에 없는 값은 지어내지 않고 "기타"로 둔다.
3. 실명이 있으면 A-001 형식의 익명 코드로 치환하고, 치환했음을 알린다.
4. 필수 6항목(활동일자·팀·활동장소·활동유형·상담자수·특이사항) 중
   빠진 것이 있으면 한 번만 되묻는다. 두 번 이상 되묻지 않는다.

### 출력 — 아래 ⓐⓑⓒ 순서 그대로

**ⓐ 활동 레코드 (JSON)**
```json
{
  "활동일자": "2026-08-16",
  "팀": "01. 서울모집홍보팀",
  "담당자": "A-001",
  "광역": "서울",
  "세부지역": "관악구",
  "활동장소": "한빛대학교",
  "활동유형": "부스운영",
  "활동시간": 3.0,
  "상담자수": 23,
  "관심표명": 9,
  "지원표명": 3,
  "포스터배포": 150,
  "기념품배부": 40,
  "특이사항": "공병 병과 관심 다수, 여학생 문의 증가"
}
```
추정한 항목에는 (추정) 표시를 붙인다.

**ⓑ 결과보고 문장 3줄**
그대로 복사해 보고할 수 있는 완결 문장. 각 줄은 1문장.

**ⓒ 되묻기** (필요할 때만)
빠진 필수 항목만 한 줄로 묻는다.

## 모드 ② — 분석 및 다음주 추천

**트리거** : "분석해줘", "다음주 어디 갈까", "추천 뽑아줘", "펀널 봐줘"

### 입력
누적 활동 레코드(JSON 배열).
누적 데이터가 없으면 assets/한빛대_시드.json 을 읽어 사용한다.
직전에 모드 ①이 만든 레코드가 있으면 거기에 더해서 계산한다.

### 처리
1. references/지표정의.md 를 읽는다.
2. 전환율 4개를 계산식 그대로 계산한다. 분모가 0이면 "—"로 둔다.
3. 추천 규칙 R1~R5를 위에서부터 순서대로 적용한다.
   먼저 걸리는 규칙이 상위 순위가 된다.
4. 표본 부족 규칙을 적용한다.
   활동 3건 미만은 제외, 3~5건은 「표본 적음(n건)」 병기.

### 출력 — 아래 ⓐⓑⓒⓓ 순서 그대로

**ⓐ 펀널 4단계**
접촉 · 상담 · 관심표명 · 지원표명의 인원 수와 전환율.
이어서 최대 이탈 구간 1곳을 지목한다.
형식) 관심표명 → 지원표명 구간에서 이탈이 가장 큽니다 (28% / 평균 35%)

**ⓑ 장소·지역별 효율 상위 3 / 하위 3**
「효율」은 상담→관심 전환율이다. 각 항목에 건수를 병기한다.

**ⓒ 다음주 추천 3순위** ← 이 스킬의 핵심 출력
각 추천마다 아래를 반드시 붙인다.
  · 추천 내용 (무엇을, 어디서, 어떤 형태로)
  · 적용된 규칙 번호 (R1~R4)
  · 근거 1줄 — [장소] — [지표명] [값] (평균 [값]) · 표본 [n]건
4순위 이하는 만들지 않는다. 규칙에 해당하는 후보가 3개 미만이면 그만큼만 낸다 — 억지로 채우지 않는다.

**ⓓ 추천 이력 레코드 (JSON)**
```json
{
  "생성시각": "2026-08-16T09:00",
  "추천내용": "한빛대학교 재방문 — 공병 병과 심화 설명회",
  "적용규칙": "R1",
  "근거지표": "상담→관심 전환율 41% (평균 28%)",
  "표본수": 6,
  "수락여부": null,
  "이후결과": null
}
```

### 금지
- 개인별 실적 순위를 내지 않는다. 팀 단위 + 「지난주의 나」 대비만.
- 근거 지표 없이 추천하지 않는다.
- 추천 이력을 개인 평가에 쓰지 않는다.

## 모드 ③ — 카드뉴스 기획안

**트리거** : "기획안 만들어줘", "카드뉴스", "1순위로 기획안", "학과설명회 기획"

### 입력 — 여기가 이 스킬의 핵심이다
모드 ②가 낸 추천 1순위 객체를 그대로 받는다.
사용자에게 학교명·학과·병과를 다시 묻지 않는다.
직전에 모드 ②를 실행하지 않았을 때만 대상을 묻는다.

### 처리
1. assets/카드뉴스.html 템플릿을 읽는다.
2. 대상학과는 추천 대상 장소의 활동 레코드 중 **가장 최근 것부터** 특이사항 필드에서
   학과명을 추출한다. 사용자에게 묻지 않는다.
   여러 건에서 서로 다른 학과가 나오면 가장 최근 레코드를 우선한다.
   특이사항 어디에도 학과명이 없을 때만 예외적으로 1회 묻는다.
3. references/코드표.md 의 「학과 → 병과 연상 규칙」으로 병과 2개를 고른다.
   이것은 "확정"이 아니라 "참고 제시"임을 반드시 표기한다.
4. 사실 정보(모집 일정·지원 자격 등)는 승인된 공식 자료에서만 인용한다.
   확인되지 않은 사실은 지어내지 않고 [확인 필요]로 표기한다.

### 출력 — 아래 ⓐ~ⓔ 순서 그대로

**ⓐ 헤드카피 3안 / 서브카피 3안**
각 안은 20자 이내. 대상 학과의 전공 언어를 쓴다.

**ⓑ 레이아웃 명세**
카드 4면 각각 1줄씩. 어떤 내용이 어디에 들어가는지만.

**ⓒ 대상별 소구 포인트 3개**
"이 학과 학생에게 특히 맞는 이유" 관점으로 각 1~2줄.

**ⓓ HTML 카드뉴스 미리보기**
assets/카드뉴스.html 의 {{자리표시자}}를 채워 완성한 HTML.
템플릿 구조를 바꾸지 않는다. 빈칸만 채운다.

**ⓔ 출처 표기**
※ 인용 : 「(문서명)」 (기준일 YYYY-MM-DD) · 검토 상태 : 초안

### 절대 넘지 않는 선
- "완성된 디자인"을 만든다고 말하지 않는다. 만드는 것은 사람이 검수할 기획안이다.
- 실제 학교명·부대명·실명을 넣지 않는다. 합성 명칭만 쓴다.

## 부속 ④ — 후속 연락 메일 초안

**트리거** : "후속 메일", "메일 초안", "협조 요청 메일"

### 입력
기관명 · 담당자 직책(실명 아님) · 접촉 이력 · 연락 목적

### 출력
**ⓐ 제목안 2개**
**ⓑ 메일 초안** — 모드 ①의 현장 수치를 본문에 인용한다.
   (예: "지난 부스 운영에서 23명과 상담하였고 …")
**ⓒ 다음 연락 권장 시점**
**ⓓ** 맨 위에 「초안 · 검토 후 사용」을 반드시 표기한다.

### 금지
- 발송 기능을 만들지 않는다. 초안 텍스트만 낸다.
  버튼이 없으면 "실수로 나갈 수 있느냐"는 질문 자체가 성립하지 않는다.
- 개인 연락처를 저장하거나 출력하지 않는다.
